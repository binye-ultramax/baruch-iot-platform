# Devices API

Registers a BMS so the platform knows its network identity (MAC address) and can hand it the two keys it needs: an **instant reading key** for live telemetry and an **activation key** for first-time pairing.

A device may be a unit we built (it has a `BMS-2026-000001` serial number from the [products API](./products-api.md)) or a third-party unit (no serial number, but a manufacturer). Both get the same kind of record.

Base URL: `https://v8yde6qhhh.execute-api.eu-west-2.amazonaws.com`

All routes require a Cognito ID token from [`POST /auth/login`](./auth-api.md):

```powershell
$BASE = "https://v8yde6qhhh.execute-api.eu-west-2.amazonaws.com"
$login = Invoke-RestMethod -Method Post -Uri "$BASE/auth/login" -ContentType "application/json" `
  -Body '{"email":"research@ultramax.co.uk","password":"Baruch2026!"}'
$headers = @{ Authorization = "Bearer $($login.idToken)" }
```

---

## Device ids

Every device gets a `deviceId` such as `dev_01JCMK3Q7X8R2N5VBHT9AZW4E6` when it is registered. It is the primary key, the way auto-increment ids are in a SQL database, except that it is generated by the function itself (a [ULID](https://github.com/ulid/spec): 48-bit timestamp + 80 random bits, Crockford base32) so no counter table or lock is needed. Ids sort by creation time.

The serial number is just a column. It is present for factory units and absent for external ones.

---

## Routes

| Method | Path | Who | Purpose |
|--------|------|-----|---------|
| `POST` | `/devices` | Administrator | Register a device, get its id and both keys |
| `GET` | `/devices/{deviceId}` | Any signed-in user | Read one device |
| `GET` | `/devices?mac=…` or `?serial=…` | Any signed-in user | Find a device |
| `POST` | `/devices/{deviceId}/activation-key` | Administrator | Issue a new activation key |
| `GET` | `/devices/{deviceId}/history` | Any signed-in user | Who did what to this device |

## Register a device

`POST /devices`

**Factory unit** — give the serial number. Model and firmware are copied from the product record.

```powershell
Invoke-RestMethod -Method Post -Uri "$BASE/devices" -Headers $headers -ContentType "application/json" `
  -Body '{"macAddress":"AA:BB:CC:DD:EE:01","serialNumber":"BMS-2026-000001"}'
```

**External unit** — no serial number, so give the manufacturer instead.

```powershell
Invoke-RestMethod -Method Post -Uri "$BASE/devices" -Headers $headers -ContentType "application/json" `
  -Body '{"macAddress":"AA:BB:CC:DD:EE:02","manufacturer":"Daly","model":"16S 100A","firmwareVersion":"2.1"}'
```

| Field | Required | Rules |
|-------|----------|-------|
| `macAddress` | yes | 12 hex digits. `AA:BB:CC:DD:EE:FF`, `AA-BB-…`, `aabb.ccdd.eeff`, and `AABBCCDDEEFF` are all accepted and stored as `AA:BB:CC:DD:EE:FF`. All-zero and all-FF are rejected. |
| `serialNumber` | one of these two | Must exist in `BmsProducts` and not be `RETIRED`. |
| `manufacturer` | one of these two | 1–64 characters. |
| `model` | no | 1–64 characters. Ignored for factory units (taken from the product). |
| `firmwareVersion` | no | 1–32 characters. |

Response `201 Created`:

```json
{
  "deviceId": "dev_01JCMK3Q7X8R2N5VBHT9AZW4E6",
  "macAddress": "AA:BB:CC:DD:EE:01",
  "serialNumber": "BMS-2026-000001",
  "origin": "FACTORY",
  "manufacturer": "Baruch",
  "model": "BMS-16S-100A",
  "activationStatus": "PENDING",
  "registeredBy": "research@ultramax.co.uk",
  "registeredAt": "2026-11-12T15:00:00.000Z",
  "updatedAt": "2026-11-12T15:00:00.000Z",
  "instantReadingKey": "Zq3…(43 chars)",
  "activationKey": "K7PM-3XQD-R9HT-WB2N"
}
```

**`instantReadingKey` and `activationKey` are shown only in this response.** Record them now. The instant reading key is stored encrypted with KMS; the activation key is stored only as a SHA-256 hash. Neither can be read back later. If an activation key is lost, [rotate it](#rotate-the-activation-key).

What happens in one DynamoDB transaction, all or nothing:

1. The device row is written to `BmsDevices`.
2. The MAC is claimed in `BmsDeviceMacs`. If it is already there, the whole request fails with `409`.
3. `DEVICE_REGISTERED` is written to `BmsAuditLog`.
4. For factory units, the product in `BmsProducts` is marked `SHIPPED` and linked to the device. If it already has a device, `409`.

## Read one device

`GET /devices/{deviceId}`

```powershell
Invoke-RestMethod -Uri "$BASE/devices/dev_01JCMK3Q7X8R2N5VBHT9AZW4E6" -Headers $headers
```

Same shape as above, without the two keys.

---

## Find a device

`GET /devices?mac=AA:BB:CC:DD:EE:01` or `GET /devices?serial=BMS-2026-000001`. Give exactly one.

```powershell
Invoke-RestMethod -Uri "$BASE/devices?mac=aa-bb-cc-dd-ee-01" -Headers $headers
Invoke-RestMethod -Uri "$BASE/devices?serial=BMS-2026-000001" -Headers $headers
```

---

## Rotate the activation key

`POST /devices/{deviceId}/activation-key` — Administrator only. The old key stops working immediately; `activationStatus` goes back to `PENDING`.

```powershell
Invoke-RestMethod -Method Post -Uri "$BASE/devices/dev_01JCMK3Q7X8R2N5VBHT9AZW4E6/activation-key" -Headers $headers
```

```json
{
  "deviceId": "dev_01JCMK3Q7X8R2N5VBHT9AZW4E6",
  "activationStatus": "PENDING",
  "updatedAt": "2026-11-13T09:00:00.000Z",
  "activationKey": "T4WN-8QHC-2MZP-F6RD"
}
```

Logged as `ACTIVATION_KEY_ROTATED`.

## History of one device

`GET /devices/{deviceId}/history` — oldest first, same format as [product history](./products-api.md#history-of-one-unit). `limit` defaults to 100, maximum 500.

```powershell
Invoke-RestMethod -Uri "$BASE/devices/dev_01JCMK3Q7X8R2N5VBHT9AZW4E6/history" -Headers $headers
```

Device actions also appear in `GET /audit?actor=email`.

## Errors

| Status | Message | When |
|--------|---------|------|
| `401` | `Unauthorized` | No token, or an expired or invalid one. |
| `403` | `Only administrators can do this.` | Register or rotate by an Operator. |
| `400` | `macAddress must be 12 hex digits, for example AA:BB:CC:DD:EE:FF.` | Bad MAC. |
| `400` | `Give a serialNumber for a factory unit, or a manufacturer for an external one.` | Neither given. |
| `400` | `deviceId must look like dev_ followed by 26 characters.` | Bad path parameter. |
| `400` | `Provide ?mac= or ?serial=.` / `Search by mac or serial, not both.` | Find with zero or two filters. |
| `404` | `No product with serial number BMS-2026-000009.` | Serial not in `BmsProducts`. |
| `404` | `No device with that id.` / `No device matches.` | |
| `409` | `Product BMS-2026-000001 is retired and cannot be registered.` | |
| `409` | `A device with MAC address AA:BB:CC:DD:EE:01 is already registered.` | |
| `409` | `Product BMS-2026-000001 has already been registered as a device.` | |

## Tables

**`BmsDevices`** — partition key `deviceId`. Index `bySerial` (`serialNumber`; sparse, factory units only). Point-in-time recovery is on.

| Attribute | Notes |
|-----------|-------|
| `deviceId` | `dev_` + 26-character ULID |
| `macAddress` | `AA:BB:CC:DD:EE:FF`, unique via `BmsDeviceMacs` |
| `serialNumber` | only for factory units |
| `origin` | `FACTORY` or `EXTERNAL` |
| `manufacturer`, `model`, `firmwareVersion` | |
| `instantReadingKey` | KMS ciphertext (key `alias/baruch-auth-device-keys`), base64 |
| `activationKeyHash` | SHA-256 of the normalized key |
| `activationStatus` | `PENDING` until the device pairs |
| `registeredBy`, `registeredAt`, `updatedAt` | |

**`BmsDeviceMacs`** — partition key `macAddress`, with `deviceId` and `registeredAt`. Exists only to make the MAC unique and to look devices up by MAC.

Device actions share **`BmsAuditLog`** with products (`subjectId` = `deviceId`).

All tables and the KMS key are kept if the stack is deleted.
